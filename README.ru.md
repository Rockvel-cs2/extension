# Расширение Rockvel

Расширение для браузера от [Rockvel](https://rockvel.store), P2P-маркета скинов CS2. Читает CS2-инвентарь в вашем браузере и отдаёт сайту, отправляет обмены Steam по вашим продажам и следит за ними. Работает в Chrome, Edge и Firefox, Manifest V3.

[English version](README.md)

Здесь лежит код каждой выпущенной версии, чтобы любой мог проверить, что расширение делает с его аккаунтом Steam. Серверы Rockvel в Steam не входят: всё, для чего нужен ваш аккаунт Steam, происходит здесь, в вашем браузере.

## Что уходит из браузера

- **Инвентарь:** из ответа Steam на сайт уходят только поля `success`, `assets`, `descriptions`, `asset_properties` и `total_inventory_count`.
- **Продажи:** id каждого созданного расширением оффера, а по сделкам, которые вы продаёте на Rockvel, и только по ним — что Steam показывает об их офферах и обменах: состояния, id предметов, Steam ID второй стороны и время. Остальная история обменов остаётся здесь.
- **Больше ничего.** Cookie Steam, ваш `sessionid` и токен Web API остаются в браузере. Разрешения `cookies` у расширения нет, и cookie оно не видит: браузер сам добавляет их к запросам в Steam. Токен расширение берёт со страницы Steam, держит только в памяти и отправляет только в API самого Steam.

## Сборка

```bash
npm install
npm run build
npm test
```

Сборка делает из одного кода две папки: `dist` для Chrome и Edge и `dist-firefox` для Firefox. Манифест для Firefox строится из `manifest.json` в `build.mjs`.

## Как загрузить в Chrome и Edge

1. Собрать, как выше.
2. Открыть `chrome://extensions` (в Edge `edge://extensions`) и включить режим разработчика.
3. Нажать «Загрузить распакованное расширение» и выбрать папку `dist`.
4. Открыть сайт и войти через Steam.

После пересборки нажать на карточке расширения «Обновить» и перезагрузить страницу сайта.

## Как загрузить в Firefox и браузеры на его базе

Проверено в Zen 1.24b (Gecko 159).

1. Собрать, как выше.
2. Открыть `about:debugging#/runtime/this-firefox`.
3. Нажать «Загрузить временное дополнение» и выбрать файл `dist-firefox/manifest.json`.
4. Открыть сайт и войти через Steam: у каждого браузера свои cookie, поэтому войти надо и на сайт, и в Steam.

Временное дополнение пропадает после перезапуска браузера. Постоянно Firefox держит только подписанные дополнения, подпись даёт `addons.mozilla.org`. Если браузер позволяет выключить проверку (Zen позволяет, обычный Firefox эту настройку игнорирует), поставьте в `about:config` `xpinstall.signatures.required` в `false`, упакуйте содержимое `dist-firefox` в zip и установите файл из меню-шестерёнки на `about:addons`. Настройка разрешает любые неподписанные дополнения, не только это.

## Что происходит

**Инвентарь.**

1. Страница инвентаря передаёт расширению Steam ID того, кто вошёл на сайт.
2. Расширение читает `steamcommunity.com/inventory/<steam_id>/730/2` постранично, а браузер сам добавляет к этим запросам cookie Steam.
3. Страница получает только поля из списка выше и отправляет их на сайт.

**Обмен.**

1. На странице сделок продавец нажимает «Отправить». Сайт передаёт расширению id заказа и Steam ID того, кто вошёл.
2. Расширение читает `steamcommunity.com`: кто вошёл в Steam и какой у него `sessionid`. Другой аккаунт Steam получает отказ.
3. Расширение создаёт один оффер со всеми продажами, которые ждут этого покупателя: Steam держит не больше 5 открытых офферов одному человеку. Оффер оно запоминает в `chrome.storage` и записывает на сайт. Покупатель увидит оффер только после Steam Guard продавца, поэтому оффер по сделке, отменённой за это время, сайт отклоняет, и расширение отменяет его раньше, чем его кто-то примет. Записанным оффер считается только по ответу сайта, а до него продавец видит просьбу не подтверждать обмен. Сообщение оффера называет номера его заказов, как обе стороны видят их на сайте, например `Rockvel #1a2b3c4d #5e6f7a8b`. Номера, которые не влезли в 128 знаков Steam, заменяет «+N».
4. Каждые 3 минуты, а пока оффер ждёт Steam Guard или покупателя — каждые полминуты, расширение один раз смотрит в Steam, сколько бы вкладок его ни просили. Сначала оно доносит до сайта незаписанные офферы, потом спрашивает, за какими продажами следить. Есть за чем следить: читает `GetTradeOffers` и `GetTradeHistory` с токеном Web API постранично до самой старой продажи, не больше 5 страниц, и сообщает только то, что касается этих продаж. Если следить не за чем, в Steam запросов нет.
5. Отчёт уходит и пустым, и с причиной, почему Steam не прочитан: по нему сайт отличает «ничего не случилось» от «никто не смотрит».
6. О новой продаже и об оффере, который покупатель не принял за 24 часа, расширение сообщает уведомлением.

Сайт сначала спрашивает версию расширения и отказывает копии старее самой ранней версии, с которой он работает. Копии в браузерах людей сайт обновить не может, поэтому это единственный способ отключить версию с ошибкой.

Правило в `rules.json` ставит заголовок `Referer` на запрос создания оффера: без него Steam отказывает, а код его поставить не может. Правило действует только на запросы самого расширения. В Firefox то же правило ставится перед каждой отправкой оффера на время сессии браузера (`allowReferer` в `src/trades.ts`).

Обращаться к расширению могут только страницы из `externally_connectable`: `rockvel.store`, а при разработке `localhost:4000`. Другие расширения не могут.

| Разрешение | Зачем |
|---|---|
| `steamcommunity.com` | Инвентарь, сессия Steam, создание и отмена оффера |
| `api.steampowered.com` | Офферы и история обменов |
| `rockvel.store`, `localhost:4000` | Продажи и отчёты о них: запросы из фона идут с cookie сессии сайта |
| `alarms` | Проверка раз в 3 минуты, а пока оффер ждёт — раз в полминуты |
| `storage` | Адрес сайта, незаписанные офферы и то, о чём вам уже сказано |
| `notifications` | Новые продажи и офферы без ответа |
| `declarativeNetRequestWithHostAccess` | Заголовок `Referer` у запроса, который создаёт оффер |

## Чем отличается Firefox

- Вместо service worker работает фоновый скрипт.
- `externally_connectable` нет ([баг 1319168](https://bugzil.la/1319168)), поэтому страница не может обратиться к расширению напрямую. Это делает `src/content.ts`: ставит на `<html>` атрибут `data-rockvel-extension` с версией расширения, принимает запросы страницы через `window.postMessage`, передаёт их фоновому скрипту и возвращает каждый ответ по id запроса.
- Контент-скрипту нужен доступ к страницам сайта, поэтому Firefox показывает их среди разрешений.
- Шаблоны адресов Firefox не поддерживают порт ([баг 1362809](https://bugzil.la/1362809)). В `matches` и правах на хост стоит `http://localhost/*`, а `include_globs` оставляет контент-скрипт только на `localhost:4000`.
- У каждой установки свой адрес `moz-extension://<uuid>`, а не id из ключа. Правило `Referer` ставится на этот адрес, а сайт принимает отчёты расширения с любого `moz-extension://`: такой `Origin` сайт подделать не может, а расширение без прав на сайт не получит cookie сессии.
- `onMessageExternal` в Firefox открыт другим расширениям, поэтому расширение отвечает только сайту и своему контент-скрипту.

## Id расширения

В Chrome и Edge id следует из `key` в `manifest.json`, поэтому он одинаков у всех, кто загрузил папку, и сайт обращается к расширению по нему. Закрытый ключ не хранится: распакованному расширению он не нужен, а Chrome Web Store при публикации выдаст свой ключ и id. В Firefox id — `extension@rockvel.store`, он задан в `build.mjs`.

## Выпуски

Rockvel разрабатывает расширение вместе с сайтом и выкладывает сюда каждую версию одним коммитом с тегом `v<версия>`.

## Авторство

Схема связи с сайтом, мост через `postMessage` для Firefox, чтение с cookie продавца, форма создания оффера, правило `Referer` и чтение обменов через токен Web API сделаны по образцу [csfloat/extension](https://github.com/csfloat/extension) (MIT, © CSFloat Inc.). Код не скопирован.
